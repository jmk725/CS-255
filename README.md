The DriverPass project was created for a new company that wanted to improve student success rates on DMV driving tests. The client asked for a complete training and scheduling system that would provide online practice exams, online courses, and in-person driving lessons. They wanted the system to support multiple types of users—students, secretaries, instructors, the IT officer, and the owner—so that scheduling, reporting, account management, and DMV updates could all be handled in one place.
One area I feel I did particularly well was describing the technical requirements of the system. I clearly identified the need for cloud hosting, a relational database, encryption, and role-based access. This helped ensure that the system would be secure, scalable, and accessible across different platforms. If I could revise one part of my work, I would expand the UML diagrams with more detailed relationships and annotations. While they illustrate the system’s processes and structure, adding more detail would make them even clearer for both technical and nontechnical audiences.
To interpret the user’s needs, I focused on the interview transcript and the business requirements, translating the client’s real-world goals into system features such as scheduling, tracking progress, and integrating DMV updates. It was important to design with the user’s perspective in mind because the system’s success depends on being practical, reliable, and easy to use. If the design did not address actual needs—like avoiding double-booked lessons or keeping test questions current—it would not add value to the business.
When I approach software design, I try to blend process models and object models. I use process models to map out how different people interact with the system and where decision points occur, while object models help me structure data and define relationships between different parts of the system. Going forward, I plan to continue using these strategies, along with strong documentation, UML diagrams, and user stories. These techniques make it easier to analyze needs, communicate ideas clearly to both clients and developers, and create designs that can be reliably implemented.
